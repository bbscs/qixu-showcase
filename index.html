栖序 Qixu

一个 Windows 桌面陪伴项目，用 Live2D 呈现角色，接入可切换的语言模型和本地语音，并在用户设定的时机主动开口。

查看系统架构 了解制作流程

系统架构

栖序用 Electron 和 TypeScript 划分角色呈现、主进程协调、对话状态和外部能力。展开各层可查看消息如何交接。

  1. 交互与呈现Live2D / WebGL

    透明角色窗绘制 Live2D。管理窗发送聊天请求并更新流式回复，本机 CLI 可以查询状态和应用配置。

  2. 桌面主进程Electron IPC

    主进程管理窗口生命周期，通过受限 IPC 接收操作。请求由主进程校验并交给对话或配置模块处理。

  3. 对话与本地状态会话与调度

    对话模块裁剪上下文、处理流式回复与取消，并记录请求终态。主动问候受勿扰、频率和会话忙碌状态约束。

  4. 能力适配模型、语音与工具

    适配层连接可切换的模型提供者和本机语音服务。工具调用由应用校验，MCP 连接器由用户管理。

一条消息如何变成回复

  1. 接收消息
  2. 组装上下文
  3. 流式显示
  4. 确认终态并落盘
  5. 按设置朗读

让主动陪伴有节制

主动搭话纳入同一对话，遵守暂停、频率和勿扰等规则。用户正在输入或已有请求时延后触发，避免同时开启两轮生成。

区分上下文和记忆

请求使用有限的会话上下文。长期记忆由显式操作管理，用户可以查看、更正或删除条目。

让跨进程权限可检查

桌面渲染通过受限接口请求主进程能力。工具和连接器由应用管理，模型输出经过应用校验后才进入执行路径。

Live2D 与本地语音

模型制作与桌面接入

将图层拆分并绑定到变形器和参数，用参数曲线驱动眨眼、双轴视线与待机。导出后在透明实窗检查姿态、贴图和物理效果。

01图层拆分拆分可动部位
02参数绑定网格与变形器
03动作与物理视线、眨眼与待机
04桌面验证透明渲染与恢复

工程难点 窗口可见与渲染器就绪是两个状态。主进程在渲染器握手后下发初始化信息，让隐藏启动后的窗口也能恢复角色。

语音队列与模型生命周期

桌面端把朗读任务交给本机语音服务。语音模型按需加载，连续朗读时复用，超过空闲阈值后卸载并释放模型显存。

合成状态示意
选择语音服务状态

服务就绪 → 加载模型 → 合成
服务启动和模型加载分别测量，便于定位首句延迟。

复用模型 → 合成
短间隔内沿用同一模型，省去重复加载。

空闲检查 → 卸载模型
服务仍可接收请求，下次合成时重新加载模型。

工程验证

用模拟故障检查恢复逻辑，用打包实窗和少量真实请求检查产品链路。

跨进程与窗口生命周期
验证角色窗隐藏后重启、从管理窗恢复显示、切换角色资源及正常退出。
真实对话与短程上下文
用合成资料测试打包程序连接真实模型，检查流式增量、终态和第二轮对第一轮的引用。
本地语音与资源回收
分别验证服务冷启动、模型冷加载和相邻两句的复用，通过服务状态与运行日志区分阶段。
升级与回退
在隔离资料副本上演练兼容，核对关键数据摘要，保留旧入口与可复验的回退路径。
