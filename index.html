DESKTOP COMPANION / WINDOWS

栖序Qixu

一个懂得何时开口的桌面伙伴。

栖序把 Live2D 角色、可换的语言模型和本地语音放进 Windows 桌面。主动问候有节奏，聊天状态可恢复，工具调用和本地资料访问由明确的规则约束。

查看系统架构 ↓ 了解制作流程 ↗

01 / SYSTEM ARCHITECTURE

一条对话，四层职责。

用 Electron 和 TypeScript 把渲染、对话编排、持久化与外部能力分开。角色窗专注呈现，管理窗负责交互，本机控制入口提供可检查的配置与状态。

  2. 02

  3. 03

REQUEST TRACE / 请求链路

输入消息 → 组装有限上下文 → 请求模型并流式显示 → 确认终态并写入会话 → 可选本地朗读

让主动陪伴有节制

主动搭话纳入同一对话，遵守暂停、频率和勿扰等规则。用户正在输入或已有请求时延后触发，避免同时开启两轮生成。

区分上下文和记忆

请求使用有限的会话上下文。长期记忆由显式操作管理，用户可以查看、更正或删除条目。

让跨进程权限可检查

桌面渲染通过受限接口请求主进程能力。工具和连接器由应用管理，模型输出经过应用校验后才进入执行路径。

02 / RENDERING & SPEECH

从参数到动作，从文本到语音。

两条技术流程独立于对话模型，分别解决桌面渲染和本机语音合成的问题。

A / LIVE2D

模型制作与桌面接入

将图层拆分并绑定到变形器和参数，用参数曲线驱动眨眼、双轴视线与待机。导出后在透明实窗检查姿态、贴图和物理效果。

01图层拆分拆分可动部位
02参数绑定网格与变形器
03动作与物理视线、眨眼与待机
04桌面验证透明渲染与恢复

工程难点 窗口可见与渲染器就绪是两个状态。主进程在渲染器握手后下发初始化信息，让隐藏启动后的窗口也能恢复角色。

B / LOCAL TTS

语音队列与模型生命周期

桌面端把朗读任务交给本机语音服务。按需加载模型，连续朗读复用已加载的模型，超过空闲阈值后释放模型显存。

合成状态示意INTERACTIVE / 无音频
选择语音服务状态

服务就绪 → 加载模型 → 合成
服务启动和模型加载分别测量，便于定位首句延迟。

复用模型 → 合成
短间隔内沿用同一模型，省去重复加载。

空闲检查 → 卸载模型
服务仍可接收请求，下次合成时重新加载模型。

03 / VERIFICATION

用真实链路检验设计。

从模拟故障到打包实窗，再到有限真实服务调用。每一层都有独立的验收范围。

跨进程与窗口生命周期
验证角色窗隐藏后重启、从管理窗恢复显示、切换角色资源及正常退出。
真实对话与短程上下文
用合成资料测试打包程序连接真实模型，检查流式增量、终态和第二轮对第一轮的引用。
本地语音与资源回收
分别验证服务冷启动、模型冷加载和相邻两句的复用，通过服务状态与运行日志区分阶段。
升级与回退
在隔离资料副本上演练兼容，核对关键数据摘要，保留旧入口与可复验的回退路径。
